# MO2610 报告与工作台 PnL 对账（2026-10-16）

## 输入与边界

- 原报告：`MO2610_期权情景分析报告.docx`。建仓日 2026-10-14，到期日 2026-10-16，指数 6905.17 点；每个情景推进 1 天，因此 `T0=2/365`、`T1=1/365`。合约乘数 100 元/点，PnL 相对报告中的入场中间价计算，不计费用。
- 逐档 IV：`options_strategy_workbench/report.csv`（GB18030）。DOCX 没有列出每条腿的 IV、无风险利率和股息率，不能仅凭 DOCX 唯一重现 BSM 结果。本对账取当前 MO 固定股息率 `q=1.1%`，假设年化无风险利率 `r=1.65%`；该利率用于统一比较，不声称是原报告实际输入。把 `r` 改为 1.8% 后，六个结果每项只变动约 0.01–1.55 元，无法解释报告差异。
- 独立 Python 实现采用标准库 `math.erf` 计算正态 CDF，按每条腿的 `sigma_i + IV变动`、`S0 × (1+指数变动)` 和 `T1` 计算 BSM 价格，再求 `Σ 方向 × (情景理论价−入场价) × 100`。脚本读取 DOCX 中的组合、情景和原报告 PnL，以及 CSV 中的逐档 IV。

## 找到的错误与差异

1. **期权链导入错列。** 原 CSV 的 Call 一侧先有“历史波动率 22.19%”，后有“隐含波动率”。旧解析器用宽泛的“波动率”匹配，取了前者，导致 Chrome 里已导入的 26 档 Call IV 全是 22.19%。以情景②铁鹰为例，错误 IV 下 Python 与修正前页面均为约 **−2,905.55 元**；Call IV 改为逐档原值后为约 **−3,010.88 元**。解析器现只接受“隐含波动率”或独立 `IV` 列。当前 Chrome 工作台的既有 26 档 Call IV 已按原 CSV 更正，原有组合和入场权利金保留；其他浏览器里旧的本地状态需要重新导入源 CSV。
2. **报告与已保存 Bear Call 不是同一组合。** DOCX 的 Bear Call 是卖 C7000（39.4）、买 C7200（6.4），净权利金和最大盈利 **3,300 元**。Chrome Strategy Library 的 `bear call` 实际保存为卖 C6900（80.8）、买 C7100（16.2），净权利金和最大盈利 **6,460 元**。报告情景①、②、⑥的 Bear Call 盈利超过 3,300 元，因此不可能是报告所列 C7000/C7200 组合的同到期结构结果；报告的 +6,460 和 −13,540 还恰好等于已保存 C6900/C7100 的两端到期界限。后者是线索，不能据此证明报告当时完整的计算过程。
3. **模型与保存快照混用。** 检查时 Chrome 当前组合设为 Black–76、`r=1.8%`；报告写 BSM。已保存的 `bear call` 是 BSM、`r=1.66%`、现货 6905.17；已保存的 `short iron condor` 是 Black–76、`r=1.66%`、现货 4300、远期 6905。两条保存记录均未保存估值日。页面现在直接展示每个保存组合的腿、保存现货、模型和利率，避免把不同快照当作同一策略。
4. **铁鹰方向命名反了。** 卖内侧 Call/Put、买两翼属于空头铁鹰（收权利金）；旧界面标为“LONG IRON CONDOR”，风险说明也跟着反了。分类和铁蝶同类命名已改正。期权策略结构参见 [Options Industry Council 的 Short Condor 定义](https://www.optionseducation.org/strategies/all-strategies/short-condor)。
5. **Black–76 到期坐标不一致。** 到期前用远期定价，但 `scenarioPnl` 到期时曾改用现货计算内在价值。现已按所选模型统一：BSM 用现货，Black–76 用远期。

## 复现

```sh
python3 reports/07_mo2610_python_bsm_reconcile.py
cd options_strategy_workbench && npm test && npm run build
```

Python 脚本需要本机已有的 `python-docx`、原 DOCX 和 GB18030 CSV。原报告第 5.2–6 节的情景 PnL、概率加权结论及基于旧 PnL 的归因不宜继续作为已验证结果；原 DOCX 本次未改写。
